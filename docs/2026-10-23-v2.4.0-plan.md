# SceneBlock v2.4.0 approved implementation plan

Goal: layer character actions/poses over base motion with editable time ranges, fix shared cut boundaries, rename projects.
Constraints: edit only new v2.4.0 folder; preserve old versions/ZIP/SceneBlock repo and root documents; no deploy/push/models. Existing clips remain base sequential track; actor.layers ordered bottom-to-top, last layer wins same joints. Each layer {id,name,mask,weight,enabled,clips}; masks full/upper/leftArm/rightArm/head. Overlay clips same action/motion/pose structure plus optional fadeIn/fadeOut; route depends ONLY base clips. pose application adds/updates overlay and keeps base. Separate explicit stationary full-pose action retained.

- [x] Core: validate layers, half-open active resolution, fade strength; legacy files unchanged; tests for 1-10walk/4-8wave/8-10turn and boundaries/mute/conflicts.
- [x] Rendering: base first then masked quaternion blending bottom-to-top; preserve legs/root during upper gestures; target retargeted static poses, procedural actions, imported motion; deterministic seeking. Upper turn is looking back, no route direction change.
- [x] UI: base+named layer lanes, add/select/edit/move/trim/remove/mute/reorder, mask strength fade controls; pose action does not erase base. Shared cut edges ripple only immediate adjacent contiguous neighbor while preserving outer bounds/min .1.
- [x] Project name: default titleless, accessible click/keyboard rename, cancel and empty handling; scene composition no longer overwrites name with prompt. Existing named projects retain name; save/open/undo.
- [x] Verify actual browser scenario, legs preserve walking under wave, pose overlay, boundary drag both directions, undo/save/open/export; regression and unit tests/build/source package, manifests.

Interfaces: resolveActorLayers(actor,time) returns [{...clip,layerId,mask,weight,localTime}] ascending array order. evaluateActor returns overlays from resolver. applyActorOverlays(model,overlays,{applyPose}) in src layer renderer runs AFTER existing base application. UI uses layers array same schema. Core owns core+new layers module; stage worker owns stage+new layer renderer; UI worker owns directing-ui/directing-operations/new layer css. Root owns app/project names/integration tests/docs/package. Independent review after implementation.
